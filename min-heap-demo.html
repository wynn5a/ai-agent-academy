Core concepts

The two rules that define a min-heap — shape and order.

Invariant 1

Complete binary tree

Every level is full except possibly the last, which is filled left → right. That shape lets us store the tree in a dense array with no pointers.

Invariant 2

Heap-order property

For every index i, A[parent(i)] ≤ A[i]. The root is always the global minimum. Siblings have no ordering guarantee.

Restore

Bubble up (sift up)

After insert at the end: while the node is smaller than its parent, swap upward. Stops when order is restored or the root is reached. O(log n).

Restore

Sift down (bubble down)

After replacing the root: repeatedly swap with the smaller child until both children are ≥ current, or a leaf is reached. O(log n).

Build

Heapify bottom-up

Start from the last non-leaf ⌊n/2⌋−1 and sift down to the root. Most nodes are near the leaves, so total work is O(n) — not O(n log n).

Contrast

Min vs max heap

Same shape; only the comparison flips. Max-heap: parent ≥ children (root is max). Priority queues pick min or max based on problem needs.

Array indexing (0-based): parent of i is ⌊(i−1)/2⌋, left child 2i+1, right child 2i+2. Level of index i is ⌊log₂(i+1)⌋. Height of an n-node heap is ⌊log₂ n⌋.

Operations & complexity

What each call does and how expensive it is in a binary heap.

Operation What happens Time Space
peek / find-min Return A[0] without mutation O(1) O(1)
insert / push Append, then bubble up O(log n) O(1)
extract-min / pop Save root, move last to root, sift down O(log n) O(1)
decrease-key Lower value at index, bubble up O(log n) O(1)
delete (arbitrary) Decrease to −∞, extract-min (or swap with last + restore) O(log n) O(1)
build-heap / heapify Bottom-up sift down from last non-leaf O(n) O(1)
heap-sort Build max-heap, repeatedly swap root with end O(n log n) O(1)
merge two heaps Concatenate arrays + heapify (binary heap) O(n + m) O(n + m)
Interview trap: n successive inserts is O(n log n). Building from an array with heapify is O(n). Prefer buildHeap when you already have all elements.

TypeScript implementation

Generic, well-typed binary min-heap with every common operation. The playground runs the same algorithms.

/** Binary min-heap over a dense array. Comparator defaults to numeric ascending. */
export class MinHeap<T> {
  private data: T[] = [];
  private readonly compare: (a: T, b: T) => number;

  constructor(compare?: (a: T, b: T) => number, items?: readonly T[]) {
    this.compare = compare ?? ((a, b) => (a as number) - (b as number));
    if (items?.length) this.build(items);
  }

  get size(): number { return this.data.length; }
  isEmpty(): boolean { return this.data.length === 0; }
  toArray(): readonly T[] { return [...this.data]; }

  /** O(1) — smallest element, or undefined if empty. */
  peek(): T | undefined { return this.data[0]; }

  /** O(log n) — append then restore heap order upward. */
  insert(value: T): void {
    this.data.push(value);
    this.bubbleUp(this.data.length - 1);
  }

  /** O(log n) — remove and return the minimum. */
  extractMin(): T | undefined {
    if (this.data.length === 0) return undefined;
    if (this.data.length === 1) return this.data.pop();
    const min = this.data[0];
    this.data[0] = this.data.pop()!;
    this.siftDown(0);
    return min;
  }

  /** O(log n) — lower the key at index (must become smaller / higher priority). */
  decreaseKey(index: number, newValue: T): void {
    this.assertIndex(index);
    if (this.compare(newValue, this.data[index]) > 0) {
      throw new Error("decreaseKey requires a smaller (or equal) value");
    }
    this.data[index] = newValue;
    this.bubbleUp(index);
  }

  /** O(log n) — remove arbitrary index. */
  deleteAt(index: number): T | undefined {
    this.assertIndex(index);
    const last = this.data.length - 1;
    if (index === last) return this.data.pop();
    const removed = this.data[index];
    this.data[index] = this.data.pop()!;
    // May need to go either direction after the swap
    const p = this.parent(index);
    if (index > 0 && this.compare(this.data[index], this.data[p]) < 0) {
      this.bubbleUp(index);
    } else {
      this.siftDown(index);
    }
    return removed;
  }

  /** O(n) — replace contents and heapify in linear time. */
  build(items: readonly T[]): void {
    this.data = [...items];
    for (let i = Math.floor(this.data.length / 2) - 1; i >= 0; i--) {
      this.siftDown(i);
    }
  }

  clear(): void { this.data = []; }

  // ── internals ──────────────────────────────────────────
  private parent(i: number) { return Math.floor((i - 1) / 2); }
  private left(i: number) { return 2 * i + 1; }
  private right(i: number) { return 2 * i + 2; }

  private bubbleUp(i: number): void {
    while (i > 0) {
      const p = this.parent(i);
      if (this.compare(this.data[i], this.data[p]) >= 0) break;
      this.swap(i, p);
      i = p;
    }
  }

  private siftDown(i: number): void {
    const n = this.data.length;
    for (;;) {
      const l = this.left(i), r = this.right(i);
      let smallest = i;
      if (l < n && this.compare(this.data[l], this.data[smallest]) < 0) smallest = l;
      if (r < n && this.compare(this.data[r], this.data[smallest]) < 0) smallest = r;
      if (smallest === i) break;
      this.swap(i, smallest);
      i = smallest;
    }
  }

  private swap(i: number, j: number): void {
    [this.data[i], this.data[j]] = [this.data[j], this.data[i]];
  }

  private assertIndex(i: number): void {
    if (!Number.isInteger(i) || i < 0 || i >= this.data.length) {
      throw new RangeError(`index ${i} out of bounds`);
    }
  }
}
// Bubble up — used by insert & decreaseKey
private bubbleUp(i: number): void {
  while (i > 0) {
    const p = Math.floor((i - 1) / 2);
    // Parent already ≤ child → heap order holds
    if (this.data[p] <= this.data[i]) break;
    [this.data[p], this.data[i]] = [this.data[i], this.data[p]];
    i = p; // continue from parent
  }
}

// Sift down — used by extractMin, deleteAt, build
private siftDown(i: number): void {
  const n = this.data.length;
  for (;;) {
    let smallest = i;
    const l = 2 * i + 1, r = 2 * i + 2;
    if (l < n && this.data[l] < this.data[smallest]) smallest = l;
    if (r < n && this.data[r] < this.data[smallest]) smallest = r;
    if (smallest === i) break; // both children ≥ current
    [this.data[i], this.data[smallest]] = [this.data[smallest], this.data[i]];
    i = smallest;
  }
}
/**
 * Why buildHeap is O(n), not O(n log n):
 * Nodes at height h cost O(h) to sift. There are ≤ n/2^{h+1} such nodes.
 * Σ h·n/2^{h+1} converges to < 2n → O(n).
 */
buildHeap<T>(items: readonly T[], compare: (a: T, b: T) => number): T[] {
  const a = [...items];
  const siftDown = (i: number) => { /* same as above */ ... };

  // Last parent is at floor(n/2) - 1
  for (let i = Math.floor(a.length / 2) - 1; i >= 0; i--) {
    siftDown(i);
  }
  return a;
}

// Contrast: n× insert is simpler but slower asymptotically
buildByInserts<T>(items: readonly T[]): MinHeap<T> {
  const h = new MinHeap<T>();
  for (const x of items) h.insert(x); // O(n log n)
  return h;
}
// Numeric priority queue
const pq = new MinHeap<number>();
pq.insert(5); pq.insert(1); pq.insert(3);
pq.peek();        // 1
pq.extractMin();  // 1

// Custom objects — Dijkstra-style
type Node = { id: string; dist: number };
const open = new MinHeap<Node>((a, b) => a.dist - b.dist);
open.insert({ id: "A", dist: 0 });
open.insert({ id: "B", dist: 7 });
open.extractMin(); // { id: "A", dist: 0 }

// Top-K largest with a min-heap of size K
function topK(nums: number[], k: number): number[] {
  const h = new MinHeap<number>();
  for (const x of nums) {
    h.insert(x);
    if (h.size > k) h.extractMin(); // drop smallest of the large ones
  }
  return h.toArray().sort((a, b) => b - a);
}

// Max-heap via inverted comparator
const maxH = new MinHeap<number>((a, b) => b - a);

Where min-heaps show up

Same structure, many algorithms — recognize the “always need the current minimum” pattern.

Graphs

Dijkstra / Prim

Open set ordered by distance or edge weight. Binary heap → O((V+E) log V). Fibonacci heap improves decrease-key theoretically; binary is what you ship.

Streaming

Top-K / median

Min-heap of size K tracks the K largest. Two heaps (max + min) maintain the running median in O(log n) per update.

Systems

Schedulers & timers

Event loops, task queues, and TTL caches: next deadline is always at the root. Extract when due, insert new timers freely.

Compression

Huffman coding

Repeatedly extract the two lightest trees, merge, re-insert. Heap makes each step O(log n).

Sorting

Heap sort & k-way merge

Heap sort is in-place O(n log n). Merging k sorted lists: push heads into a min-heap, pop smallest, push next from that list.

Agents / AI

Priority tool queues

When an agent ranks pending actions by cost, urgency, or confidence, a min-heap is the natural “what next?” structure.

Not a search tree: Heaps do not support efficient arbitrary lookup, range queries, or ordered traversal of all elements. For those, use a BST / TreeMap. Heaps optimize “access extreme + insert/delete extreme.”
